Flagged for Review

Items below were flagged during repository verification and reconstruction for GitHub Pages. Nothing here blocks the site — the scoreboard, game view, and replay feed are live and working (see “Verified” below). Unverified items are left blank or generic by design, never inferred.

  • Missing assets/ directory in initial upload: The initial commit (uploaded tree) contained index.html, game.html, reviews.html, 404.html, README.md, and server.mjs, but omitted assets/css/style.css and assets/js/*.js. All referenced static assets were reconstructed to match the HTML interfaces and official MLB StatsAPI endpoints.
  • Static GitHub Pages hosting: GitHub Pages serves static files only and does not execute server.mjs. Browser-side persistence uses localStorage via assets/js/feed-log.js. The local persistence server (node server.mjs) works locally (health, feed-log GET/POST, 404 fallback verified) but has no effect on the Pages deployment.
  • Original behavior unverified. The upstream repository returned 404. The reconstructed scripts are not a verified copy. In particular the matchup panel does not implement the forecast described in the uploaded README, and advanced replay tracking is not verified.
  • Incomplete game data. Inning and batting table rows link to their MLB feed. Missing fields are blank rather than zero. For an official example, compare the schedule with its game feed.

Verified (2026-11-20, final integration)

Each item below was checked against the official source linked. The live site is snapquast73-boop.github.io/LIVPBP2 (project site per GitHub Pages docs; the Pages deployment for the merged integration commit reported built).

  • Scoreboard, game view, and replay feed render with real data. Irregularities — unverified, left blank/generic (do not block)

  • README references files that are not in the repo. The uploaded README cites docs/verification-report.md, docs/api-compliance.md, docs/scoring-changes.md, docs/workflows/, tools/review-test.mjs and 12 other tools/*.mjs tests, tools/run-risk-preview.html, tools/model-calibration-report.mjs, and tools/count-model-derivation.mjs. None exist in the repo tree. Claims that depend on those files are unverified and were not recreated (recreating them would be invention).
  • Poll intervals differ from the README. The README describes 500ms/125ms/250ms watchers; the reconstructed code polls the scoreboard every 30s, the game page every 15s, and the replay feed every 30s (see assets/js/scoreboard.js, assets/js/game.js, assets/js/reviews-feed.js). The slower cadence is intentional for a public static site (it avoids hammering statsapi.mlb.com); the README’s numbers describe the original project, which could not be verified (upstream 404, above).
  • Hit forecast not implemented. The README’s two-sided hit forecast (log5, platoon splits, form, head-to-head) is not in assets/js/props.js, which shows only the current batter/pitcher and bats/throws sides (verified live on game 775296). No forecast values are shown or inferred.
  • Review-code mapping unverified. The README asserts reviewDetails codes MJ (ABS), MA/MF (manager), NH (boundary). In the live game-775296 feed the catcher-interference manager challenge (“Yankees challenged … call on the field was upheld”) renders as generic “Replay Review”, not “Manager Challenge”, and NH is not handled explicitly in assets/js/reviews.js. The raw reviewDetails payload for that play was not inspected this session, so the mapping is flagged rather than changed. Official payload: game 775296 feed.
  • Scoreboard review ticker depends on an unverified field. assets/js/scoreboard.js reads schedule flags.inReview. The verified Final-game schedule flags contains only no-hitter/perfect-game booleans (no inReview), and no live-game example was available this session (offseason) to confirm the field. If the field is absent, the scoreboard banner simply never shows (no crash); the game-page banner (feed-based) is verified working. Left as-is pending a live-game check.
  • ABS and challenges-remaining counters unverified in display. Schedule review.away/home.used/remaining is verified present (above), but the reconstructed code does not display per-team counters, and gameData.absChallenges could not be verified (game 775296 is from 2024, before ABS). The code never zero-fills absent counters. Official payloads: schedule hydrate=review, game feed.
  • Scoring-change tracker, SSE push, and 429 throttle not in the reconstructed client. The README describes a scoring-change diff tracker, a server-sent-events live push, and HTTP-429 backoff. The reconstructed client uses localStorage only (no /api/feed-log POST, no EventSource, no 429 handling); server.mjs provides the backend locally but Pages cannot run it. The SSE stream was not verified (empty in a 2s local test); the client fallback (polling) covers it. Original behavior unverified (upstream 404, above).
  • 404.html uses absolute Pages paths. 404.html links to /LIVPBP2/assets/css/style.css and /LIVPBP2/index.html (correct for the project site, where the custom 404 is served at the missing URL; other pages use relative paths). Locally (node server.mjs) the 404 page is therefore unstyled. Verified: Pages serves a 404 for unknown paths (custom 404 active); local 404 fallback verified via server.mjs.
  • Repo homepage URL is empty. The repository’s homepage field is unset (site is live at snapquast73-boop.github.io/LIVPBP2 regardless). Setting it requires repo-admin access (gh repo edit returned 403 for the integration token); set it in Settings → General → Homepage if desired. Does not affect the site.
